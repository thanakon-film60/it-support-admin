## ค้างอยู่ (เรียงตามความสำคัญ)

1. **ย้าย JSON → Postgres** — service + schema + connection pool พร้อมแล้ว เหลือเขียน adapter
   ของ `store.ts` เหตุผล: ทุก request อ่าน/เขียนทั้งไฟล์ และเขียนพร้อมกัน 2 process ข้อมูลพังได้
2. **สำรองตัวไฟล์ในคลังไฟล์** — `backup.bat` ไม่รวม volume `drive` โดยตั้งใจ ตอนนี้ต้องสั่ง
   `docker compose cp app:/app/drive <ที่เก็บนอกโปรเจกต์>` เอง ควรมีสคริปต์สำรองไปดิสก์อีกลูก/NAS
3. **รหัสทรัพย์สินซ้ำ 28 แถว** — ตอนนี้แค่ลดความเสียหายด้วยการให้ผู้ใช้เลือก ควรแก้ที่ข้อมูลต้นทาง
4. **`formatThaiDateShort` / `formatThaiDateFull` ใน `lib/utils.ts` ยังใช้เวลาเครื่อง** — เพี้ยน 7 ชม.
   เมื่อเรนเดอร์ฝั่งเซิร์ฟเวอร์ ควรย้ายไปใช้ `lib/date-th.ts`
5. **เปลี่ยนรหัส admin ตั้งต้น** ด้วย `staff-admin.bat` → "ตั้งรหัสผ่านใหม่" (โปรแกรมเตือนเองถ้ายังใช้อยู่) ·
   **ยังไม่มีตัวจำกัดจำนวนครั้งที่ล็อกอินผิด** — ควรทำก่อนแจกบัญชีหลายคน
6. **`a=my_assets` / `a=find_asset` ใน `flow.py` ไม่มีปุ่มไหนเรียกแล้ว** หลังตัดเมนูชั้น 2 ออก
   (ยังไม่มี keyword ให้พิมพ์เรียกด้วย) — ตัดสินใจว่าจะเอากลับมาหรือลบ handler ทิ้ง
7. **FAQ ยังอยู่ใน quick reply** (`messages.MENU_BUTTONS`) ทั้งที่ถอดออกจาก rich menu แล้ว —
   ถ้าจะเลิกใช้จริงต้องถอดที่นั่นด้วย
8. **`welcome_back_days` ประกาศใน `config.py` และรายงานใน `/health` แต่ไม่มีโค้ดไหนใช้เลย** —
   ใช้จริงหรือลบทิ้ง อย่าปล่อยไว้ให้คนอ่านเข้าใจผิดว่ามีฟีเจอร์นี้

### ชื่อผู้แจ้งหายจากการ์ด — แก้แล้ว 2026-10-01

**อาการที่ผู้ใช้แจ้ง:** "LINE OA ไม่โชว์ชื่อคนแจ้งเลย อยากให้เอากลับมาเพื่อจะได้รู้ว่าใครแจ้ง"

**ต้นเหตุ:** `messages.ask_description()` เอาบรรทัด `👤 แจ้งในชื่อ: ...` ไปต่อหน้า `Reply.text`
แต่ส่ง `flex=base.flex` ซึ่งเป็นการ์ดใบเดิมที่ไม่มีชื่อ — และ `line_api.to_line_messages()`
ส่ง Reply ที่มี flex เป็น **การ์ด** โดยใช้ `text` เป็น **altText** เท่านั้น
ชื่อจึงไปโผล่แค่ในหน้าจอแจ้งเตือน **คนที่เปิดแชทอยู่ไม่เคยเห็นสักครั้ง** ทั้งที่ docstring เขียนว่าแสดงให้แล้ว

| เรื่อง | รายละเอียด |
| --- | --- |
| แก้ที่ไหน | `flex.description_prompt()` รับ `requester=` แล้ววาดกล่อง "แจ้งในชื่อ" ไว้บนสุดของการ์ด · `messages.ask_description()` ประกอบการ์ดใหม่แทนการใช้ `base.flex` ซ้ำ |
| ขยายผลพร้อมกัน | `flow._requester_badge()` เดิมโชว์เฉพาะคนที่ **ผูกกับทะเบียนแล้ว** — คนที่พิมพ์ชื่อเองจึงไม่เห็นชื่อตัวเองเลยทั้งบทสนทนา และไม่ได้ปุ่ม "เปลี่ยนคนแจ้ง" ด้วย พิมพ์ผิดแล้วต้องยกเลิกเริ่มใหม่ทั้งเรื่อง · ตอนนี้โชว์ทุกครั้งที่รู้ว่าแจ้งในชื่อใคร |

### การเบิกจบที่ขั้นยืนยันผู้เบิก — ทำแล้ว 2026-09-30 (รอบบ่าย)

**ทำไมไม่ตัดทิ้ง:** ปุ่ม **"👤 เปลี่ยนคนแจ้ง"** (`a=rq_change`) ติดอยู่กับข้อความของขั้นนี้
**ที่เดียวในทั้งระบบ** (`messages.ask_description()`) ตัดขั้นตอนเมื่อไหร่ คนที่บัญชี LINE
ถูกผูกไว้ผิดคนจะไม่มีทางแก้เองในแชทอีกเลย ต้องให้แอดมินแก้ให้ทุกครั้ง และเพราะผูกครั้งเดียว
ใช้ตลอด ความผิดนั้นจะติดไปกับ ticket ทุกใบของคนนั้นจนกว่าจะมีคนสังเกต

**สิ่งที่ทำแทน:** คงขั้นตอนไว้ แต่เพิ่มปุ่ม **"✅ ไม่มี ส่งเลย"** (`a=desc_skip`) ทั้งบนการ์ด
และใน quick reply — จบด้วยการกด 1 ครั้ง ได้ความเร็วที่ผู้ทดสอบต้องการ โดยไม่เสียทางแก้ผู้แจ้ง

| เรื่อง | รายละเอียด |
| --- | --- |
| ปุ่มโผล่เมื่อไหร่ | `flow._can_skip_description()` — เบิก/คืน โผล่เสมอ · ซ่อม/ขอใช้บริการ โผล่เฉพาะตอนมี `initial_message` (เล่ามาแล้วตั้งแต่ข้อความแรก) |
| **กฎที่ห้ามพัง** | เงื่อนไขโชว์ปุ่ม **ต้องตรงกับเงื่อนไขที่ handler ยอมรับเป๊ะๆ** — ปุ่มที่กดแล้วบอทถามซ้ำแย่กว่าไม่มีปุ่ม ผู้ใช้จะสรุปว่าบอทพังแล้วเลิกใช้ · มีเทสต์ `test_ปุ่มไม่มีส่งเลยโผล่เฉพาะตอนที่กดแล้วผ่านจริง` ผูกสองอย่างนี้ไว้ด้วยกัน (4 ประเภท × เล่า/ไม่เล่า = 8 เคส) |
| ทางเข้าเดียว | ทุกจุดที่ถามรายละเอียดเรียกผ่าน `flow._ask_description(session)` เท่านั้น ห้ามเรียก `M.ask_description()` ตรงๆ ไม่งั้นจะมีเส้นทางที่ปุ่มหายไปเงียบๆ |
| จบงานทางเดียว | ทั้ง "พิมพ์ `-`" และ "กดปุ่ม" ไปจบที่ `flow._finish_description()` ตัวเดียวกัน แยกเมื่อไหร่ได้บั๊ก "พิมพ์ผ่าน แต่กดไม่ผ่าน" ทันที |
| ข้อความที่แก้พร้อมกัน | ซ่อม/ขอใช้บริการ เคยขึ้นว่า "(จำเป็นต้องระบุ)" ทั้งที่ handler ยอมให้ข้ามอยู่แล้วถ้ามี `initial_message` — แยกเป็น 2 ข้อความตามสถานะจริง |
| เทสต์ | `test_flow.py` เพิ่ม 13 เคส · รวมทั้งหมด 245 เคส เขียว |

### บั๊ก/ช่องว่างที่ตรวจเจอ 2026-09-26 (เอกสารเคยบอกว่าทำแล้ว แต่โค้ดไม่ได้ทำ)

1. **`app/events.py` (`EventGuard`) ไม่ถูก import ใน `main.py`** — กัน event ซ้ำและล็อกต่อผู้ใช้
   เขียนครบแล้วพร้อมเทสต์ แต่ยังไม่ได้ต่อเข้าระบบ `main.py` ยังใช้ `asyncio.gather()`
   ประมวลผลทุก event ขนานกัน · ผลที่ยังพอรับได้: `request_id` กัน ticket ซ้ำไว้อีกชั้นแล้ว
   **ควรต่อให้เสร็จ** เพราะ LINE ยิงซ้ำเองเมื่อไม่ได้ 200 ภายใน 1 วินาที
2. **`ai.is_greeting()` ไม่มีใครเรียก** — พิมพ์ "สวัสดีครับ" ตอน IDLE ยังถูกตีความเป็นชื่อสาขา
   (ยืนยันด้วยการรัน `flow.handle()` จริง) เป็นจุดที่คนเข้าใจว่าระบบพังแล้วออกจากแชท
3. **`welcome_back_days` ประกาศใน `config.py` และส่งออกที่ `/health` แต่ไม่มีโค้ดไหนใช้**
4. **`LINE_BOT_WEBHOOK_URL` ไม่ได้ตั้งใน `docker-compose.yml`** ทั้งที่ `route.ts` อ่านค่านี้ —
   ถ้าจะใช้ route ของ Next.js เป็นตัวส่งต่อต้องตั้งเอง (ตอนนี้ LINE ยิงเข้าบอทตรงอยู่แล้ว จึงยังไม่กระทบ)
5. **`line-bot-python/tests/e2e/run_e2e.py` ตรวจข้อความรุ่นเก่า** (พบ 2026-09-30) — ขั้น 4 รอ
   "ระบุหมายเลขทรัพย์สินครับ" และขั้น 8 รอ "ระบุชื่อผู้เบิก" ซึ่งเปลี่ยนเป็นเมนูไล่ชั้น/ทะเบียนพนักงานไปนานแล้ว
   สคริปต์จึงล้มก่อนถึงท้ายเส้น (ขั้น 9-10 อัปเดตตามการเบิกแบบใหม่แล้ว) ไม่อยู่ใน `pytest` เพราะต้องรันระบบจริง
